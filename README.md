# NOL 취소표 알리미 (nol-cancel-alert)

> 패키지·확장 이름: `nol-cancel-alert`

NOL(야놀자, 구 인터파크 티켓)에서 공연·콘서트 **취소표를 감지하고, 사람이 빠르게 예매할 수 있도록 돕는** 개인용 도구입니다.

## 실행 방법

> 현재 상태: **6단계(감시 불능 판정) 완료.** 좌석 화면에 들어가 있는 동안 조건에 맞는 취소표가 생기면 알리고, 좌석 선택 시간 만료·응답 끊김도 알립니다. 좌석 강조는 7단계에서 붙습니다. 진행 상황은 9절을 보세요.
>
> 취소표를 자동으로 잡고 싶다면 이 도구보다 먼저 NOL 공식 **예매대기**를 신청하세요 (4절).

### 준비물

| 항목 | 버전 | 용도 |
|---|---|---|
| Google Chrome | 120 이상 | 확장 실행 |
| Node.js | 24 이상 | 테스트 실행 (확장 사용에는 필요 없음) |

빌드 단계는 없습니다. `extension/` 폴더를 크롬에 그대로 불러옵니다.

### 1) 내려받기

```bash
git clone https://github.com/leesara1/nol-ticket.git
```

WSL에서 받았다면 Windows 크롬에서 `\\wsl.localhost\<배포판 이름>\...\nol-ticket\extension` 경로로 접근할 수 있습니다. 크롬이 이 경로를 불러오지 못하면 `extension/` 폴더를 Windows 쪽 폴더(예: `C:\nol-cancel-alert\extension`)로 복사해서 쓰세요.

### 2) 크롬에 확장 불러오기

1. 크롬 주소창에 `chrome://extensions` 입력
2. 오른쪽 위 **개발자 모드** 켜기
3. **압축해제된 확장 프로그램을 로드합니다** 클릭 → `extension` 폴더 선택
4. 처음 설치하면 설정 페이지가 자동으로 열립니다

### 3) 설정

설정 페이지는 확장 아이콘 우클릭 → **옵션**, 또는 `chrome://extensions`의 확장 카드 → **세부정보** → **확장 프로그램 옵션**에서 다시 열 수 있습니다.

| 항목 | 설명 |
|---|---|
| 대상 공연 | 상품코드(공연 페이지 URL의 숫자), 회차, 등급·구역·열, 연석 수, 좌석 정규식. **상품코드를 넣어야 감시합니다** |
| 알림 | 소리, 크롬 알림, 텔레그램(봇 토큰·chat_id) |
| 예매자 정보 | 예매 화면의 빈 칸 채우기용. 이 PC의 크롬에만 저장됩니다 |

저장할 때 잘못된 값은 안전한 값으로 고쳐지고, 무엇을 고쳤는지 경고로 표시됩니다.

### 4) 알림 확인

툴바의 파란 **N** 아이콘을 누르면 팝업이 열립니다. 아이콘이 안 보이면 주소창 오른쪽 퍼즐 아이콘에서 고정하세요.

| 팝업 항목 | 내용 |
|---|---|
| 대상 공연 / 알림 | 현재 설정 요약 |
| 감시 중인 탭 | 좌석 화면 탭의 감시 상태 (감시 중 / 좌석 발견 / 감시 불능) |
| **알림 테스트** | 켜 둔 채널(크롬 알림, 소리, 텔레그램)로 테스트 알림을 보내고 채널별 결과를 보여줍니다 |
| 설정 열기 | 설정 페이지 |

크롬 알림이 안 뜨면 Windows **설정 → 시스템 → 알림**에서 Chrome 알림이 켜져 있는지 확인하세요. 알림을 클릭하면 해당 탭으로 이동합니다.

### 5) 이벤트 로그

설정 페이지 아래 **이벤트 로그**에서 최근 90일 기록을 CSV(엑셀용) 또는 JSON으로 내보낼 수 있습니다. 좌석이 생기고 사라진 시각을 모아 취소표가 풀리는 시간대를 분석하는 용도입니다.

### 6) 사용

1. 설정 페이지에서 **대상 공연 상품코드**와 조건(등급·구역·연석 수 등)을 저장합니다
   - 등급은 `R`, `VIP`, `S`처럼 앞글자만 써도 됩니다 (`R` → `R석(현장수령)`)
   - 구역은 `A구역`, `9구역`, `1층`처럼 씁니다
2. 크롬에서 NOL에 로그인하고, 날짜 선택 → [예매하기] → **보안문자** → 좌석 선택 화면까지 직접 들어갑니다
3. **감시하려는 구역이 화면에 보이게** 지도를 맞춰 둡니다. 좌석맵은 화면에 보이는 구역만 약 3.8초마다 갱신합니다
4. 조건에 맞는 좌석이 새로 생기면 소리·크롬 알림·텔레그램이 오고, 해당 탭이 앞으로 옵니다
   - 들어갈 때 이미 비어 있던 좌석은 알리지 않습니다 (설정의 "감시 시작 시 이미 비어 있는 좌석도 알림"을 켜면 알림)
5. **좌석 클릭, 선택완료, 보안문자, 결제는 직접 합니다**
6. 좌석 선택 시간(10분)이 끝나면 "감시 불능" 알림이 옵니다. 다시 들어가야 합니다. 취소표가 많이 풀리는 시간대에 맞춰 들어가는 것을 권합니다
7. **좌석 탭을 화면 앞에 두세요.** 크롬은 5분 넘게 뒤에 있는 탭의 갱신을 1분에 한 번으로 줄입니다. 그러면 감지가 늦어지고 "30초 동안 응답 없음" 알림이 올 수 있습니다
8. 좌석을 찾은 뒤 결제 단계로 넘어가면 감시를 조용히 멈춥니다 (만료·끊김 알림을 보내지 않음)

확장은 페이지가 이미 받는 좌석 응답을 읽기만 합니다. 사이트에 요청을 더 보내지 않습니다.

### 코드를 고친 뒤

`chrome://extensions`의 확장 카드에서 새로고침 아이콘을 누르고, 열려 있던 NOL 탭도 새로고침합니다.

### 테스트

저장소 루트에서 실행합니다.

```bash
node --test              # 단위 테스트
node e2e/e2e.mjs         # 실제 크롬(headless Chromium)에 확장을 불러와 팝업·옵션·알림 점검
node e2e/seat-e2e.mjs    # 가짜 좌석 화면으로 취소표 감지 → 알림 전체 경로 점검 (openssl 필요)
```

`seat-e2e.mjs`는 로컬 HTTPS 서버를 `tickets.interpark.com`으로 연결해(크롬 `--host-resolver-rules`) 매진 데이터를 내주다가 좌석 두 개를 풉니다. 실제 사이트에는 접속하지 않습니다.

`e2e/e2e.mjs`는 Playwright가 내려받은 Chromium(`~/.cache/ms-playwright/chromium-*`)을 자동으로 찾습니다. 다른 경로면 `CHROME=/경로/chrome node e2e/e2e.mjs`로 실행하세요. 확장 내부 페이지만 확인하고 NOL 사이트에는 접속하지 않습니다.

## 1. 목표

- 원하는 공연·회차·좌석 조건에 맞는 취소표가 생기면 **즉시 알아챈다.**
- 알림을 받은 뒤 좌석 클릭 → 선택완료까지 **사람이 걸리는 시간을 최소화**한다.
- NOL 계정이 정지되거나 예매가 취소될 위험을 만들지 않는다.

## 2. 대상

| 항목 | 값 |
|---|---|
| 사이트 | NOL 티켓 (`nol.yanolja.com/ticket`) |
| 첫 대상 공연 | 2026 성시경 연말 콘서트 (상품코드 `26015783`) |
| 공연 기간 | 2026-12-31 ~ 2027-01-03, 올림픽공원 |
| 예매 기간 | 2026-11-12 20:00 ~ 2027-01-02 11:00 |
| 공연 설정 | `예매대기` 사용 중, `잔여석 숨김` 사용 중, 무통장입금 제외 기간 2026-11-06 ~ 2026-12-14, 2026-12-08 일괄 배송 |

## 3. 범위

### 3.1 구현 범위

| 단계 | 자동화 여부 |
|---|---|
| 취소표 감지 | 자동 |
| 알림 (소리, 데스크톱, 텔레그램) | 자동 |
| 브라우저 탭 앞으로 띄우기, 좌석으로 스크롤, 강조 표시 | 자동 |
| 좌석 클릭 | 사용자 |
| '선택완료' 클릭 | 사용자 |
| 예매자 정보 입력 | 자동 (NOL이 미리 채우지 않는 경우에만) |
| 보안문자, 결제 | 사용자 |

### 3.2 요청됐으나 현재 범위 밖인 항목

| 요구사항 | 상태 | 사유 |
|---|---|---|
| **R-X1. 조건에 맞는 좌석을 자동으로 클릭하고 '선택완료'까지 진행** | 미구현 | NOL 약관이 금지하는 매크로에 해당합니다. 탐지되면 계정 정지나 예매 취소 위험이 있고, 직접 예매하는 다른 이용자에게 불리합니다. 공식 **예매대기**(4절)가 같은 결과를 정식으로 제공합니다. |

### 3.3 만들지 않는 것

- 보안문자 자동 풀이·우회
- 봇 탐지 회피 (브라우저 지문 위장, 프록시 교체, 사람처럼 보이게 하는 무작위 지연 등)
- 짧은 간격의 반복 새로고침, 대기열 자동 통과
- 여러 계정 동시 운용
- 되팔기 목적의 사용

## 4. 먼저 할 일: 공식 예매대기

대상 공연은 NOL **예매대기**를 지원합니다. 희망 날짜와 등급을 골라 신청하고 결제 수단을 등록해 두면, 취소표가 나올 때 NOL이 서버에서 예매와 결제까지 진행한다고 알려져 있습니다. 이 내용은 블로그 글 기준이므로 신청 화면의 안내로 확인해야 합니다.

이 도구는 예매대기와 **함께** 쓰며, 예매대기로는 지정할 수 없는 조건(구역, 열, 연석)을 노릴 때 쓰는 것을 전제로 합니다.

## 5. 기능 요구사항

### 감지
- **FR-1** 사용자가 직접 연 좌석맵에서 예매 가능한 좌석 목록을 읽는다. 읽는 방법은 다음 우선순위를 따른다.
  1. 페이지가 이미 받은 네트워크 응답 (추가 요청 없음)
  2. DOM 관찰 (`MutationObserver`)
  3. 화면 픽셀 비교 (기존 `nol_screen_alert.py`, 좌석맵이 캔버스로 그려질 때만)
- **FR-2** 좌석은 `Seat {key, id, playSeq, grade, zone, block, row, col, seenAt}` 하나의 형식으로 다룬다 (정의: docs/DESIGN.md 4절).
- **FR-3** 조건 필터: 날짜·회차, 등급, 구역, 열 범위, 연석 수(N), 좌석 정규식
- **FR-4** 좌석 ID로 직전 결과와 비교해 "생김/사라짐"을 구분한다. 같은 좌석은 사라졌다가 다시 생길 때만 다시 알린다.
- **FR-5** 구조화된 데이터(네트워크, DOM)로 읽었다면 바로 확정한다. 픽셀 방식만 2회 연속 확인한다.

### 새로고침 — 해당 없음 (2026-11-16 사전 조사)
좌석맵이 보이는 구역의 좌석 상태를 약 3.8초마다 스스로 다시 받는 것을 확인했습니다 ([research/03](research/03-target-26015783.md)). 확장은 그 응답을 읽기만 하므로 자동 새로고침을 만들지 않습니다. 사이트에 보내는 추가 요청은 없습니다.
- ~~FR-6~~ ~~FR-7~~ ~~FR-8~~ 해당 없음
- **FR-9** 대기열 화면이 나오면 사용자에게 알린다 — **보류**: 정상 입장 때도 대기열 순번 응답이 오고(`myRank: 1`), 실제 대기 중 값을 확인하지 못해 판정 규칙을 정할 수 없음 (DESIGN 8)

### 알림
- **FR-10** 좌석이 생기면 소리, 크롬 알림, 텔레그램을 동시에 보낸다. 메시지 예: `R석 1층 A구역 7열 12·13번 (2연석) 생김`
- **FR-11** 감시가 불가능한 상태를 감지하면 좌석 알림과 구분해서 알린다. 대상 상태: 로그아웃, 대기열, 세션 만료, 좌석맵 파싱 실패(좌석 전체 0개), 셀렉터 불일치, 10분간 응답 없음
- **FR-12** 생존 신호: 10분 동안 정상적으로 읽은 적이 없으면 알린다.

### 보조
- **FR-13** 좌석이 감지되면 해당 크롬 창과 탭을 앞으로 띄운다.
- **FR-14** 조건에 맞는 좌석으로 스크롤하고 테두리로 강조한다. '선택완료' 버튼도 강조한다. 클릭은 하지 않는다.
- **FR-15** 예매자 정보 입력 화면에서 비어 있는 칸만 저장된 정보로 채운다. 사용자가 좌석을 클릭한 뒤에만 동작한다.

## 6. 비기능 요구사항

- **NFR-1 서버 부하:** 사이트에 보내는 추가 요청을 최소화한다. 감지는 페이지가 이미 받은 데이터를 우선 사용한다.
- **NFR-2 개인정보:** 아이디와 비밀번호를 저장하거나 명령줄 인자로 받지 않는다. 로그인 세션은 사용자의 크롬을 그대로 쓴다. 예매자 정보와 텔레그램 토큰은 로컬에만 두고 git에서 제외한다.
- **NFR-3 유지보수:** 셀렉터와 엔드포인트는 코드가 아닌 설정 파일에 둔다.
- **NFR-4 테스트:** 사전 조사에서 저장한 HAR, HTML, 스크린샷으로 오프라인 테스트한다. 개발 중에는 실제 사이트에 반복해서 요청하지 않는다.
- **NFR-5 기록:** 좌석이 감지된 시각을 기록해 취소표가 풀리는 시간대를 분석할 수 있게 한다.

## 7. 구조

```
Chrome (사용자 프로필, 로그인 상태)
 └─ MV3 확장 "nol-cancel-alert"
     ├─ content script (all_frames)
     │   ├─ net   : 페이지가 받은 좌석 응답 읽기 (읽기만, 재전송 없음)   [기본]
     │   ├─ dom   : MutationObserver                                   [예비]
     │   └─ state : 로그인 / 대기열 / 세션 만료 / 파싱 실패 감지 → "감시 불능"
     ├─ service worker
     │   ├─ detector  : 조건 필터, 좌석 ID 비교
     │   ├─ notifier  : 소리 + chrome.notifications + 텔레그램, 생존 신호
     │   └─ assist    : 탭 포커스, 스크롤·강조, 클릭 후 예매자 정보 채우기
     └─ options page  : 조건, 시간대, 텔레그램 토큰, 예매자 정보

Python (Windows, 선택)
 └─ nol_screen_alert.py : 캔버스 좌석맵용 픽셀 감시 (예비 수단)
```

크롬 확장을 쓰는 이유: 크롬 136부터 기본 프로필에서는 `--remote-debugging-port`가 동작하지 않습니다. 그래서 Playwright로 "로그인된 내 크롬에 연결"하기가 번거롭고, 확장은 탭 제어와 알림도 기본으로 제공합니다.
